# Audio System and Settings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a restrained electronic-arcade soundtrack, differentiated combat/UI effects, English match announcements, and persistent Master/Music/SFX/Voice controls in the existing console-style UI.

**Architecture:** A focused `AudioManager` node owns buses, playback, music transitions, voice ducking and versioned settings while `main.gd` requests semantic cues from match and screen flow. Original deterministic WAV assets are generated by a repository tool; the settings screen remains in `main.gd` so it can reuse the established console helpers without duplicating the visual system.

**Tech Stack:** Godot 4.7 GDScript, Godot audio buses and `AudioStreamPlayer`, Python 3 standard-library WAV generation, GDScript headless tests, Python `unittest`.

**Spec:** `docs/superpowers/specs/2026-10-09-audio-settings-design.md`

## Global Constraints

- Preserve the 1280x720 reference layout under `canvas_items` plus `expand`; anchor edge UI and keep 1280-wide screens centered.
- Keep all UI forced left-to-right on Hebrew/RTL systems.
- Reuse `_screen_title`, `_split_background`, `_bottom_bar`, `_primary_button`, `_secondary_button`, and `scripts/ui/ornament.gd`; introduce no new settings visual language.
- Opening settings from pause must leave combat, timers, CPU, animations, round transitions and finishers frozen; Back returns to pause and does not resume.
- Existing finisher sound timing, hit ownership, cleanup, celebration and pause contracts do not change.
- Announcer copy is exactly `ROUND ONE`, `ROUND TWO`, `FINAL ROUND`, `FIGHT!`, `YOU WIN`, and `YOU LOSE`; never `ROUND THREE`.
- Audio must be original or compatibly licensed, restrained in loudness, and must not imitate an identifiable real person.
- Missing or unreadable optional audio must warn and never block screen or match progression.

## Review Focus

- A corrupted settings file with mixed valid and invalid fields preserves the valid fields and safely defaults or clamps only the invalid ones; Task 1 tests it.
- Rapid slider motion neither writes to disk nor retriggers previews for every pointer event; Task 5 tests preview throttling and commit-only persistence.
- Entering settings from pause and backing out through Escape never unpauses the tree or advances the round clock; Task 5 tests both paths.
- Overlapping attacks do not cut each other's effects off, and missing cue files do not stop combat; Tasks 2 and 3 test polyphony and missing-cue behavior.
- Low-health tension does not repeatedly restart or stack when health oscillates around the threshold; Task 4 tests idempotent music state changes.
